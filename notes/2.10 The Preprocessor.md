When compiled, the program actually goes through the preprocessor first. The preprocessor makes temporary changes to the code -- none of which are actually changes to the original program document. 

Most of these changes are rather unintersting, for example it strips out comments and ensures each newline actually appears on a newline. It also interprets what #include means

The preprocessor outputs a translation unit, and this is then compiled. 

The entire process of preprocessing, compiling, and linking is called translation

When the preprocessor runs it looks for **preprocessor directives;** these start which a # and may or may not resemble c++ syntax

# Macros
#define can be used to create a macro
In c++, a macro defines how input text is converted into output replacement text
There are:
- Object-like macros
- function-like macros

Function-like macro's use is generally unsafe and in their use cases it is typically better to just use a function

Object-like macros can be defined in two ways
\#define IDENTIFIER
\#define IDENTIFIER substituionText
\* Note that neither ends with a semicolon, as they are preprocessor directives and have different syntax to typical c++ code

- Naming syntax for typical identifier applies to macro names; although, by convention they are all uppercase and use underscores

Using object-like macros with substitution text was popular in C, but there are better methods which will be later acknowledge, and thus, it is best practice to avoid the use of object-like macros with substitution identifiers

## Object-like macros without substitution text
These are useful for the use cases explored above, but they have specific use cases and are still practical to use

There exists conditional compilation directives which will return a true or false type of thing if an identifier has been defined
int main()
{
\#define BOB
\#ifdef BOB
	Do something 1;
\#endif
\#ifdef JOE
	Do something 2;
\#endif
	return 0;
}
This will do something 1 but not something 2

There is also \#ifndef which is if not defined
There is also alternative syntax:
- \#if defined(BOB) and \#if !defined(BOB)

A common use of conditional compilation directives is to block out a block of code from being compiled:
\#if 0
	none of this code will be compiled
\#endif

This is perfect to block out code which already contains multi-line code

To temporarily re-allow this code to be compiled one can replace the 0 with a 1
ie) \#if 1 ... \#endif

\* Note In most cases, macro substitution does not occur when a macro identifier is used within another preprocessor command.

Since preprocessor directives don't care about c++ syntax they don't care about being used in/not in functions and whatnot
