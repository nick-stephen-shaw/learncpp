Two identifiers cannot be identical -- this is called a naming collision
- Example used: think that two streets cannot have the same name

If two or more functions or global variables share a name, the program will not compile

Some things help us avoid naming collisions:
- Scope regions
	- If identifiers share a name but never a scope, then everything works fine
		- Example: two identical street names in different cities
- Namespaces
	- A namespace may only contain declarations and definitions. Executable statements are only allowed as part of a definition (e.g. of a function).
	- Namespaces allow another scope (called namespace scope) that allows you to declare and define names inside of it

Any name that is not defined within a function, class, or namespace is automatically considered to be apart of the global namespace; also called global scope


When you use an identifier that exists outside of the global or local namespace you must indicate such to the compiler
- For example, cout is located within the standard (std) namespace, thus std::cout
- :: is the scope resolution operator
- The name to the right is the namespace which the object on the right is located within

Although variables can be defined in the global namespace, generally they should be avoided -- this will be explored in more detail later. 

You can also use using directions `` using namespace std;`` but this is discouraged as it may cause any identifier -- even ones that are yet to be added -- to cause a compiling conflict
