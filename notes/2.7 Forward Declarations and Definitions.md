The problem arises because programs are executed sequentially. Say function A calls B and function B calls A, there is no possible manner in which the program can be organized such that this code compiles. Hence, we must use a forward declaration. 

A forward declaration tells the compiler about an identifier before it is defined.

A forward declaration for functions looks like this:
- int function(parameter);
Note the semicolon and the lack of a function body
Note also that the parameters do not have to be given their proper names either (int, int) works as well as (int x, int y) but the latter is preferred for clarity's sake

Function declarations are practically a copy/pasted version of the function header with an added semicolon which tell the compiler that the function exists. 

Other than simply ordering problems, often times function declaration is necessary because the program is using a function that is defined in a separate file. 

There exists other types of forward declarations (with types other than just functions) -- those will be covered later

All definitions are also declarations

Not all declarations are definitions

The One Definition Rule:
- With one *file* each variable, function, object, can only have one definition in a given scope
- Within a *program* each function or variable in a given scope can only have one definition
- Types, templates, inline functions, and inline variables are allowed to have duplicate definitions in different files, so long as each definition is identical. We haven’t covered what most of these things are yet, so don’t worry about this for now -- we’ll bring it back up when it’s relevant.
